## 一、它解决什么问题

学生问 AI「什么是变量」，AI 立刻给出一段完美解释。学生点头，觉得自己懂了 ——
但换一道题还是不会。**这是"假性掌握"：答案来得越容易，理解越浅。**

小问号反过来做：

| 传统 AI 助教 | 小问号 |
|---|---|
| 学生问 → AI 答 | 学生答 → AI 问 |
| 输出一段解释 | 输出**一个**问题 |
| 学生被动接收 | 学生主动建构 |
| 看不出哪里没懂 | 每一次"说不清"都被记下来 |

它的工作方式是 **G-Loop**：

```
提问（苏格拉底）→ 学生回答 → 诊断缺口 → 更新图谱 → 决定下一问
        ↑                                              ↓
        └──── 讲不清 → 回到追问 ← 费曼环节（学生讲给 AI 听）← 疑似懂了
```

## 二、三个核心创新

### 1. 认知缺口图谱：把"没懂"变成可追踪的证据
不是聊天记录，而是把学生的每一句话结构化成**缺口事件**，归入小学版 7 类：

| 类型 | 含义 | 小学生典型表现 |
|---|---|---|
| 定义缺失 | 说不出"是什么" | 「就是……电脑里面放东西的地方吧」 |
| 机制不清 | 说不出"怎么工作" | 「因为……加了就更难猜？」 |
| 类比失效 | 打比方打错地方 | 把"放进去"当成"加上去" |
| 术语依赖 | 用没懂的词解释词 | 「电脑有内存，就记住了」 |
| 因果想当然 | 把先后当因果 | 「因为电脑是先发明 0 和 1 的」 |
| 边界模糊 | 不知道何时不适用 | 「密码加生日更安全，因为更长了」 |
| 迁移失败 | 换个情境就不会 | 会做这道，换个说法就不会 |

每条缺口都带着**学生原话引用**、发现轮次、闭合轮次，形成可追溯的证据链。

### 2. 拒答护栏：把"不给答案"变成可测量的数字

"AI 不给答案"很容易说，很难**证明**。小问号内置护栏，边聊边统计五项指标：

| 指标 | 定义 | 目标 | 实测 |
|---|---|---|---|
| 答问比 Q/A | 疑问句数 ÷ 结论句数 | ≥ 3 | **60 – 90** |
| 泄露率 Leak Rate | 直接给答案的轮次占比 | ≤ 5% | **0%** |
| **诱导率 Leading Rate** | 把答案藏进问句的轮次占比 | ≤ 10% | **0%** |
| **一问一题率** | 只含一个问号的轮次占比 | ≥ 95% | **100%** |
| 缺口闭合率 | 已闭合缺口 ÷ 诊断出的缺口 | ≥ 60% | **100%** |

> **为什么"诱导率"必须单独算**：把答案藏进问句（"是不是因为……所以……？"）在字面上完全合法——
> 没有结论句、以问号结尾、答问比很高。但它比直接给答案更糟：学生以为自己在思考，其实只是在点头。
> 多数"苏格拉底式 AI"恰恰栽在这里，而它无法用"是否给了答案"检测出来。

> 数据来源：`pnpm selfcheck`，在 5 段回放脚本共 **39 轮**对话上自动统计，护栏通过率 **39/39 = 100%**，结果可复现。
> 前端交互经 puppeteer 冒烟测试验证：**14 项全通过，零控制台错误**（`node scripts/smoke.mjs`）；
> 已部署的线上链接另经浏览器实测 **7 项全通过**（`node scripts/smoke-live.mjs <url>`）。

### 3. 费曼环节：让学生教 AI

当学生疑似掌握，AI 切换到「从没学过的同桌」角色，请学生讲给它听。
AI 只在**含糊/术语依赖/逻辑断链**处打断，对应费曼技巧第 3 步「回到材料」。

通过标准三条全满足：无未定义术语 + 有生活类比 + 能回答变式追问。

## 三、怎么保证"引导是准的"：分析交给代码，表达交给模型

只靠 Prompt 让大模型"像苏格拉底一样提问"，会稳定地犯三个错：
**诱导式提问**（答案藏进问句）、**一问多题**（一句话问三件事）、**原地打转**（反复问同一个问题）。
这些错误靠"再写一段更长的 Prompt"是治不住的。

所以小问号把教学决策拆成两层：

```
学生回答  →  【规则层】分类 + 决策（代码，稳定可复现）
                     ↓  "这一轮该用哪种提问动作"
                   【模型层】把这个动作说成孩子听得懂的一句话
```

### 3.1 概念知识库：让提问有据可依

每个概念都有一份"教学底稿"（`src/core/concepts.ts`）：

| 字段 | 作用 |
|---|---|
| `checkpoints` | 真懂必须说到的那几句话 —— 用来判掌握，**不靠模型的感觉** |
| `jargon` | 小学生不该随口用的词 —— 术语审计词表 |
| `misconceptions` | 已知的典型错法 + 对应的反问 —— 精准下刀，不用瞎猜 |
| `ladder` | 每一层台阶上这个概念可以问什么（含"再不会就退到"的备选问法） |
| `feynmanProbes` | 费曼环节"同桌"可以追问的变式，验证能不能迁移 |

现已覆盖 6 个概念：变量、循环、算法、二进制、密码安全、人工智能。

### 3.2 回答分类 → 提问动作矩阵

学生每说一句，规则层先判 8 种状态，再决定用哪一招：

| 学生状态 | 判定依据 | 该用的动作 |
|---|---|---|
| 说不会 | 显式表达 | **降阶重问**（换说法，不换目标） |
| 踩典型错法 | 命中 `misconceptions` 的表述 | **给反例**（让他自己发现矛盾） |
| 用了术语 | 命中 `jargon` 且未解释 | **请澄清**（"这个词是什么意思呀"） |
| 背规则 | 复述规则但无理由 | **追问理由** |
| 说到一半 | 命中部分必答点 | **追问后果**（专攻还缺的那一点） |
| 说全了 | 必答点全覆盖 | 先**换情境**验证迁移，再进费曼 |
| 跑题 / 太笼统 | — | 拉回来 / 要具体例子 |

这一步把"引导是否准确"从模型的手感，变成了可测试的矩阵。

### 3.3 费曼学习法：真正落实第三、四步

费曼技巧是四步：**选概念 → 讲给外行 → 发现讲不清就回去补 → 简化重讲**。
多数 AI 实现只做了第二步（听一遍，说"很棒"），把最关键的第三、四步丢了。
小问号的做法是：

1. **规则层先评分**，四维加权，每一维都给依据，不是模型说过了就算过：

   | 维度 | 权重 | 判定依据 |
   |---|---|---|
   | 外行能听懂 | 30% | 有没有用同桌听不懂的词（术语审计） |
   | 关键点说全 | 35% | 命中了几个必答理解点 |
   | 有生活类比 | 15% | 有没有打比方 |
   | 说清了为什么 | 20% | 有没有因果/机制说明 |

2. **不通过就退回重讲**，并精确指出卡在哪一句（照抄原话）+ 下一句问什么
3. 最多重讲 3 轮；仍不通则退回追问补最弱的点，**不硬逼**

实测判定能清楚分开三档质量：**19 分 / 61 分 / 88 分**（`pnpm selfcheck` 可复现）。

### 3.4 教学复盘：把引导过程变成可复核的证据

每次对话结束可导出教师报告：缺口按类型归并、**哪种提问动作最有效**、
下一步该从哪里教。每个判断都能点回学生原话，不需要模型再总结一遍。

**三个模型角色**（同一模型，靠 Prompt + 结构化输出切换）：

| 角色 | 职责 | 输出 |
|---|---|---|
| Socratic Engine | 把规则层指定的提问动作说成一句话 | `{say, intent}` |
| Gap Diagnoser | 补充诊断规则层看不出的细微缺口 | `{gaps[{type,evidence,confidence}], understood_level}` |
| Feynman Reviewer | 扮演不懂的同桌，只在断链处打断 | `{say, stuck_at, missing}` |

**规则层**（不调用模型，纯代码）：

| 模块 | 职责 |
|---|---|
| `concepts.ts` | 概念知识库：必答点 / 术语表 / 典型错法 / 分层问法 |
| `socratic.ts` | 回答分类 → 提问动作矩阵 + 诱导式提问检测 |
| `feynman.ts` | 费曼四维评分 + 回环控制 |
| `guardrail.ts` | 五项指标审计 |
| `teacher-report.ts` | 教师复盘报告 |

### 为什么浏览器直连

API Key 只存在用户自己的 `localStorage`，**不经任何中间服务器**。
对小学生场景，这意味着对话数据不落第三方、无需后端运维、评委可零成本部署。

### 体验模式

内置 5 段完整回放脚本（变量 / 密码安全 / 二进制 / 循环 / 人工智能初步），**不需要 API Key、不依赖网络模型**，
评委打开链接点「播放完整过程」即可看到 G-Loop 全流程与图谱动态生长。

## 六、场景与内容

对标《义务教育信息科技课程标准（2022 年版）》，学段 3–6 年级，已内置：

1. **算法与程序**：变量、循环、算法、调试
2. **数据与编码**：二进制、编码解码
3. **网络与安全**：密码安全、个人信息保护
4. **人工智能初步**：AI 是怎么学的、数据从哪来
5. **数字设备与信息**：文件整理、搜索甄别

## 七、儿童保护设计

- **挫败防护**：连续 2 轮答不上来自动降层，换更浅的说法重问同一件事；只给"最小提示"，绝不给完整答案
- **无社交、不采集个人信息**，对话数据只留在本地浏览器
- **语言公约**：一句话 25 字内，禁止抽象术语，术语必须翻译成动作（"变量"→"贴了名字的盒子"）

## 八、与已有开源项目的差异

开源界已有苏格拉底提问（[socratic-workshop](https://github.com/smashburger-dev/socratic-workshop)、[m4vic/socratic](https://github.com/m4vic/socratic)）
与费曼技巧（[feynman-tutor](https://github.com/koukekoukej-glitch/feynman-tutor)）的**单引擎**实现。小问号的差异在于：

1. **缺口结构化**：把"没懂"落成 7 类可追踪、可量化、可闭合的缺口事件，而非一次性提示
2. **护栏可审计**：用答问比 / 泄露率 / 闭合率三个数字自证"真的不给答案"，评委可当场验证
3. **场景落地**：面向小学信息科技，含儿童语言公约与挫败防护，对标 2022 义教新课标
