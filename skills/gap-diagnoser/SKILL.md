# 认知缺口诊断器

## 用途

把学习者的「没懂」从模糊印象变成**可追踪、可量化、可闭合的结构化事件**。

## 何时使用

- 学习者回答后，需要判断他哪里其实没懂
- 需要决定是否进入费曼环节（理解度 ≥ 0.7 且无未闭合缺口）
- 需要生成学习报告 / 教师复盘

## 7 类缺口

| id | 名称 | 判定信号 |
|---|---|---|
| `def` | 定义缺失 | 说不出"它是什么"；回答含糊、空泛、只重复问题 |
| `mech` | 机制不清 | 知道名字，说不出"它怎么工作" |
| `analogy` | 类比失效 | 给了类比，但关键属性对不上 |
| `jargon` | 术语依赖 | 用了他自己也没解释过的术语 |
| `causal` | 因果想当然 | 把时间先后当成因果，或因果倒置 |
| `edge` | 边界模糊 | 知道它有用，不知道它什么时候不适用 |
| `transfer` | 迁移失败 | 会做这道，换个情境就不会 |

## 判定规则

1. **证据必须是学生原话片段，照抄不改写**。找不到原话就不报这个缺口。
2. 一次最多报 2 个缺口，没有就不报，**不要凑数**。
3. 学生真的说清楚了 → 返回空数组。
4. 判定 `jargon` 的关键：他用的词他自己没解释（如「电脑有内存，就记住了」）。
5. 判定 `causal` 的关键：他的"因为"其实只是把问题重复了一遍，或只是时间顺序。

## 输出契约

```json
{
  "gaps": [
    { "type": "mech", "evidence": "学生原话片段，≤30 字", "confidence": 0.85, "need_ask": true }
  ],
  "understood_level": 0.6,
  "note": "一句话点评（20 字内）"
}
```

## 去重与闭合

同一 `type` + 相似证据视为同一缺口，不重复记账。
后续学生把它讲清楚了 → 标记 `resolved`，记录 `resolvedRound`。

闭合率 = 已闭合缺口 ÷ 诊断出的缺口总数。这是系统级指标，目标 ≥ 60%。

## 常见误判（避免）

| 误判 | 为什么错 |
|---|---|
| 学生说得短 → 判 `def` | 短不等于不懂，要看是否命中关键点 |
| 学生用了术语 → 判 `jargon` | 若他随后用自己的话解释了，就不算 |
| 学生答错 → 判 `mech` | 要看错在哪个环节，可能是 `analogy` 或 `edge` |
| 为了凑指标报缺口 | 假缺口会污染闭合率，宁缺毋滥 |
