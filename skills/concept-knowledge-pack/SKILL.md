# 概念教学底稿

## 用途

只靠 Prompt 让模型"问得好"是不够的：它不知道这个概念在小学生身上有哪几种典型错法，
也不知道什么样的回答算真懂。结果就是：**问得很流畅，但问不到点上；判得很自信，但判错。**

底稿的作用是给模型一份"教学地图"，让它从**自由发挥**变成**在地图上选择与追问**。

## 六个字段

| 字段 | 作用 | 缺了会怎样 |
|---|---|---|
| `checkpoints` | 真懂必须说到的那几句话（含必答/加分） | 无法判断掌握，只能靠模型感觉 |
| `jargon` | 不该随口用、用了就说明没懂的词 | 抓不到"用术语解释术语" |
| `misconceptions` | 已知典型错法 + 对应反问 | 只能瞎猜，问不到痛处 |
| `analogies` | 好用的生活类比 | 模型给出孩子没见过的比方 |
| `ladder` | 每层台阶可以问什么（含"更不会时退到"） | 难度控制失控 |
| `feynmanProbes` | 费曼环节的变式追问 | 无法验证能否迁移 |

## 编写要点

### 1. checkpoints 要写成"能验证的话"，不是"知识点"

| ✗ 太抽象 | ✓ 可验证 |
|---|---|
| 理解变量的赋值语义 | 放新值会覆盖旧值（关键词：覆盖/替换/挤掉/旧的没） |
| 掌握循环的三要素 | 有停止条件（关键词：停/为止/结束/数到） |

关键词要收窄到"说出来就说明懂了"的词，不要放泛词（"知道""理解""明白"）。

### 2. misconceptions 必须带反问，且反问不能含答案

```json
{
  "label": "把\"放进去\"当成\"加上去\"",
  "detect": ["加起来", "加上", "相加", "等于8"],
  "gapType": "mech",
  "probe": "注意，是\"放进去\"，不是\"倒进去\"。你觉得盒子里的旧东西会怎么样？"
}
```

`probe` 是"戳破它的问法"，**不是答案**。写的时候自查一遍：
学生照着这个反问想，会不会直接得到答案？如果会，重写。

### 3. ladder 每一层都要给"更不会时"的备选

```json
{
  "level": 3,
  "intent": "用具体数值逼出覆盖 vs 相加",
  "ask": "盒子里先放着 5，我现在把 3 放进去。你觉得盒子现在是什么样？",
  "easier": "是变成 3，还是变成 8，还是别的？"
}
```

`easier` 只降低**语言难度**，不降低**认知目标**。

### 4. 术语黑名单要区分"概念名"和"术语依赖"

概念名本身（"变量"）在讲解时出现是正常的，不该判为术语依赖。
只有**用它去解释别的东西**时才算。代码里要处理这个区别。

## 扩展新概念

1. 先找 3 个真实学生，问一遍，把他们**说错的原话**记下来 —— 这是错法的最好来源
2. 写下"能讲给同桌听懂的版本"，从中抽出 3–4 个必答点
3. 每个必答点配 3–6 个关键词（要具体，别放泛词）
4. 每个错法配一个好反问（不含答案）
5. 跑 `pnpm selfcheck`，看新概念下护栏和费曼判定是否仍然达标
